# CMS 简洁后台实施计划

**目标：** 落实用户已确认的四个主入口、统一网站切换、集中预览与发布、日常编辑隐藏技术配置。

**范围：** 现有 Vue 管理端的导航与交互；复用 Studio、媒体、工作区、发布 API。沿用现有权限、草稿保存、版本冲突与发布检查。

## 任务与验证

- [ ] 导航：修改 `ui/src/layouts/dashboard/navigation.ts`、`aside-content.tsx`、`index.tsx`；主导航为工作台、网站内容、素材库、设置；模型和插件嵌入高级工具。先扩展 `ui/test/dashboard-navigation.test.mjs`，验证旧内容深链仍选中网站内容、媒体旧链接归属一致、无关路径不误匹配。
- [ ] 网站切换：新增 `site-picker.ts`、`site-picker.tsx`；按明确工作区 selector 加载有权限的站点，加载失败可重试，选择时保留离开页面的草稿拦截，校验后再通过 SDK 切换。测试跨区 selector、部分失败和错误隔离。
- [ ] 内容：修改 `ui/src/views/dashboard/studio.tsx`，业务分类使用中文名称；页面内容和设置共用编辑入口，分别保存时保留另一标签未保存内容；品牌资料可直接进入编辑；保留原完整编辑器作为高级入口。
- [ ] 素材与设置：复用完整素材管理入口；编辑器内打开已有上传弹窗并刷新素材选择；网站设置直接连接品牌、域名、成员，技术配置折叠。
- [ ] 样式：沿用 `design-system/cms-studio/MASTER.md`，补充网站选择弹窗、内容标签、固定发布按钮和移动端布局。
- [ ] 验收：运行 `cd ui && node --test test/*.test.mjs`、`npm run build`、相关文件 ESLint 和 `git diff --check`；使用本地隔离 Mongo fixture 验证导航、站点切换、草稿离开拦截、页面双标签、素材上传与发布检查，记录截图与结果。

## 约束

- 不新增后端业务接口或修改服务端权限。
- 不自动执行发布、回滚或生产部署。
- 页面与内容分别调用原 API，不将顺序调用宣称为原子保存。
- 网站切换使用路由离开钩子，用户取消离开时不得调用 SDK 清空缓存或改变工作区。
