# FireGuard 消防设备生产验收计划

目标：新增独立 FireGuard 模板，在生产 CMS 导入，编辑六个消防产品，使用 AI 生成图片并上传媒体库，完成独立站发布和公网验收。

## 已确定的范围

- 域名：`fire.novaintelligent.cn`。由用户配置 Cloudflare；预期 A 记录 `fire → 101.33.78.203`，开启代理。源站当前证书的 SAN 包含 `*.novaintelligent.cn`。
- 独立工作区与站点：`FireGuard 消防设备`。CMS 站点 ID：`12e0921b-270f-46f4-864c-8b5716178b31`。
- 模板：`fireguard@1.0.0`，沿用已支持的五模型与发布快照协议，采用暖白、石墨和消防红设计。
- 产品：便携式干粉灭火器、二氧化碳灭火器、消防水带、消火栓箱、烟感报警器、应急照明灯。
- 图片：六张产品图和一张首页图，CLI/API 生成，逐张检查后上传生产 CMS 媒体库，再由内容条目选择引用。
- 展示文案不声明未核实的产品认证、性能或机构背书；图片及价格明确标为展示及参考用途。

## 执行顺序

1. 发布 CMS 兼容性修复：保留公开仓库、不可变来源、摘要、schema 与路由检查，允许独立模板 ID。
2. 完成 FireGuard 模板及动态发布目标。运行 schema、隔离、预览、构建与候选镜像检查，审查通过后合入 master。
3. 使用用户指定的生图服务生成七张图片，保留提示词及文件对照。将首页图作为模板资产，更新 manifest checksum；生产内容图片经媒体库上传引入。
4. 发布独立 GHCR 镜像，核验来源证明与匿名拉取，再登记不可变 registry。FireGuard 不使用现有仅允许 AeroFrame 的服务器预拉取通道。
5. 在新 CMS 站点选择 FireGuard 并导入，编辑六产品、分类、首页、关于页面及品牌信息；检查全部图片均引用媒体库条目。
6. 通过服务器管理通道配置新域名入口、Gateway Site/Domain 与 CMS 对该站点的发布绑定。当前 CMS env 只绑定现有商城，不能直接替换该绑定，否则会影响商城。
7. 执行发布预检、保存不可变版本、等待 Gateway 候选实例通过健康检查，再切换公开路由。
8. 公网检查：首页、目录、六产品、关于页面、图片下载、草稿隔离、移动端布局；保存结果与截图。

## 当前执行状态

全部八个执行步骤已完成。FireGuard 1.0.0 已合 master、推送并通过公开镜像发布；七图已生成并上传媒体库；六款产品及配套内容经生产 CMS UI 保存；独立域名已验证并发布九页面。最终活动 release 为 `76bf91b5-6710-4600-9bdd-44a873e76a37`，revision 2，原商城仍为 revision 4。

实际公网页面、媒体哈希、404、草稿隔离及390像素生产视口交互检查通过。CMS 同版本草稿预览未支持 FireGuard，媒体初始化与多选控件可视状态另有管理端缺陷，已在验收报告记录，未将这些功能标为通过。

## 完成判定

只有生产 CMS 中存在六个已编辑产品、七张生成图片已上传且被内容引用、FireGuard 独立站发布成功，并通过实际公网检查后，才将本次生产端到端验收记为通过。CLI dry-run、本地 fixture 和内置发布版本均不能代替此判定。
