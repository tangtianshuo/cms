# 公开模板仓库：Subagent 任务拆分

> 本文件拆分[中文实施方案](./2026-10-26-公开模板仓库独立站实施方案.md)的执行任务，不授权修改远端可见性、提交/推送、发布镜像、写生产配置或切换流量。任务状态均为未开始。主 Agent 在每个任务的代码和验收结果上复核，只有通过闸门才下发依赖任务。下文路径以 `d:\Projects\Nova\cms` 和 `d:\Projects\Nova\storefront-templates` 为根。不同仓库不要共享未协调的工作树。

**目标：** 平台统一管理公开模板源码与清单、公开 GHCR 镜像；各公司独立部署 CMS 和网关，在本地 CMS 中引入和发布，不使用 R2 发布索引。

**执行规则：** 每个代码任务先做失败用例，再做最小实现并运行相关验证；不得碰其他任务拥有的文件。所有回报写明更改文件、测试命令/结果、未解决风险；不要自动提交。实际远端操作须由主 Agent 获取明确批准后执行。涉及真实密钥不得读取值或打印到日志。现有 `cms` 文档有未提交修改，执行时保留。

## 依赖图

```text
A1 公开前只读审计 ───> G0 人工审计/公开批准 ───> A4 真实远端发布验证
A2 回归基线 ────────┘                       │
A3 共享发布契约 ──> B1 Git 发布索引 ──> B2 GHCR CI ──┘
         │                  │
         │                  └──> C1 CMS 验证读取 ──> C2 CMS 引入/草稿 ──> C3 CMS UI
         └──────────────────────> D1 网关契约 ──> D2 部署/快照/切流
                                                        │
                                                   D3 域名/迁移 ──> G3 上线验收
```

- A1、A2、A3 只读调查可以并行；A3 提交契约结论前需对照 A1、A2 的结果。A1 不扫描或输出未跟踪私有配置的内容。
- B1 与 D1 可在 A3 契约批准后分别在模板仓库和独立网关仓库开展；C1 需要 B1 的固定版本样本。B2 与 C1 可在不同文件、不同仓库并行；C2 必须等待 C1；C3 等待 C2 后端契约。
- G0 未通过之前 B1/B2 仅做本地开发与 CI 草案，不得公开仓库或发布镜像。D1/D2 实施前必须确认独立网关仓库的本地 checkout；不存在时只交付接口设计，不伪称已部署。
- 每个阶段安排独立复核：需求对照、跨公司数据隔离/信任边界复核、测试证据复核。不得由同一 subagent 在共享工作树并发修改同一文件。

## 阶段 0：调查与授权

### A1（general_purpose_task，只读）：公开前历史与许可审计

**范围：** 模板仓库的已跟踪树、所有拟公开 refs 的 Git 历史、现有忽略规则；只审计，不改文件、不改仓库可见性。使用可信历史 secret 扫描器，记录工具/版本/扫描范围及风险摘要，人工复核许可、内网地址、客户内容。发现疑似凭据只报告文件/提交和类型，不展示值；真实泄漏交由负责人轮换和处置。检查是否存在本地未跟踪私有配置，但不得读取其内容。

**交付：** 公开阻断项列表、历史扫描覆盖范围、需要人工确认的许可及凭据问题。**验收：** 所有待公开 refs 均被覆盖，风险已分类；未经审计不建议直接将私有仓库改公开。

### A2（general_purpose_task，只读）：本地与 Linux CI 基线

**范围：** CMS 现有契约测试和后端 `npm run build:noEmit`，模板仓库 `npm test`、`npm run validate`、Docker 构建与独立镜像烟测；确认 Linux CI 对 Windows 跳过的符号链接用例的结果。只运行测试，不更改实现、不 push。

**交付：** 具体命令、通过/失败/跳过项、环境限制、旧站点发布/回滚/域名的现有接口基线。**验收：** 失败项有可重现证据；未运行的远端测试明确标为未验证，不以本地通过代替远端发布。

### A3（search agent，只读）：冻结跨仓库发布契约

**范围：** 对照 `storefront-templates/scripts/validate.mjs`、`scripts/publish.mjs`、`schema/template.schema.json`、`templates/aeroframe/1.0.0/template.json`，以及 `cms/backend/src/presets/catalog.ts`、`import.ts`、`site-model.ts`、`releases.ts`、`controller.ts`。确定索引记录、规范化 JSON/SHA-256、资源完整性、模板 ID/version、镜像 digest 和 CMS 版本兼容字段的准确语义；明确现有模板 JSON 缺少 CMS `theme/demo` 的映射方案及入口验证边界。

**交付：** 一页契约决策及固定测试向量，列明仍需平台确认的身份验证方式；不臆造已存在的公开索引。**验收：** B1、C1、D1 可独立引用同一测试向量；发现不一致先交主 Agent 决策，不同时在两个仓库各造一套格式。

### G0（主 Agent + 负责人，人工闸门）

确认 A1 无未处理的真实泄漏或许可障碍、必要的密钥已轮换、仓库/分支保护与发布写权限落实；**单独请求批准**公开 Git 仓库和 GHCR 镜像。此闸门不是子 agent 的自动操作。

## 阶段 1：平台发布

### B1（general_purpose_task，模板仓库独占）：Git 版本索引及不可变校验

**前置：** A3 契约冻结。**文件所有权：** `scripts/publish.mjs`、`scripts/validate.mjs`、`schema/template.schema.json`、`test/publish.test.mjs`、`test/validate.test.mjs`；需要公开索引文件时在模板仓库新增最小文件，不动 workflow。

**任务：** 测试驱动实现固定版本清单与索引的校验/生成：只允许 `available` 记录指向已验证清单及 digest；同一 ID/version 变更拒绝，重复发布幂等；处理并发写入冲突；失败不会留下可见的 `available` 记录。受保护 Git 提交/PR 负责索引更新，不把内存 store 冒充远端 CAS 存储。**验证：** `npm test`、`npm run validate`，覆盖篡改、重复、未就绪及竞态。**交付：** 确定的清单路径/示例记录/测试结果。

### B2（general_purpose_task，模板仓库 workflow 独占）：GHCR 构建与发布流水线

**前置：** B1 的索引契约可用；G0 之前只能做本地/PR 验证。**文件所有权：** `.github/workflows/template-release.yml`、Docker 构建相关现有文件及新的 workflow 测试（如必须）。不修改 B1 拥有的 `scripts/publish.mjs` 和索引格式。

**任务：** CI 先校验/测试/扫描/烟测，再推送公开 GHCR，读取远端 digest，验证可核验的构建身份/签名，最后经受保护的变更更新索引。使用最小权限的 CI 身份，不打印凭据；失败不得暴露 `available`，已引用版本不自动删除。**验证：** PR 校验和失败路径、本地镜像烟测；真实 push 与匿名 pull 留待 G0 之后 A4。**交付：** 工作流、权限说明与 CI 证据，不宣称已发布。

### A4（主 Agent 串行执行/人工授权）：首次非生产远端验收

**前置：** G0、B1、B2。经单独远端操作授权后，验证 CI 成功发布、匿名取得清单/镜像、checksum 与 digest/来源相符、同版本重跑无差异、失败候选不可见、历史版本仍可拉取。此项不可由无权限的 subagent 标为完成；不能将本地烟测冒充远端验收。

## 阶段 2：公司 CMS

### C1（general_purpose_task，CMS 后端读取契约）：固定发布源验证

**前置：** A3、B1 的固定索引样本。**文件所有权：** `backend/src/presets/catalog.ts` 附近的只读适配模块与对应测试；仅增加接口，不修改 `import.ts`/UI。

**任务：** 先写测试，再实现固定可信发布源的公开索引与版本清单读取、checksum/schema/兼容范围验证、失败关闭及验证过的目录缓存。拒绝用户输入任意 URL、任意分支/tag、篡改清单；旧内置 preset 仍可读取。**验证：** 读取契约的单测与 `npm run build:noEmit`（cwd `cms/backend`）。**交付：** 可调用的解析/验证接口、离线/损坏输入测试证据。

### C2（general_purpose_task，CMS 导入所有权）：版本映射和工作空间引入

**前置：** C1 验证接口。**文件所有权：** `backend/src/presets/import.ts`、`controller.ts`、`site-model.ts` 及同目录相关测试，协调 `pages.ts`；不得改 C1 的只读模块。

**任务：** 映射公开清单的模型/字段/页面与可选示例 Entry 到当前 CMS 契约，记录 ID/version/checksum/digest，保留旧 preset 行为。租户鉴权后生成本公司草稿；重复导入幂等、不覆盖编辑；公司预览须鉴权，发布仍需校验/生成不可变内容 Release。**验证：** 工作空间隔离、冲突/重试、草稿和旧站回归测试，`npm run build:noEmit`。**交付：** API 契约及两个工作空间互不影响的证据。

### C3（general_purpose_task，CMS UI 独占）：模板选择/预览/引入页面

**前置：** C2 的 API 契约。**文件所有权：** `ui/src/views/dashboard/presets.tsx` 和其直接依赖的 UI 测试/样式，不修改后端。

**任务：** 登录公司 CMS 中选择已发布模板版本，展示公共演示/本公司私有草稿预览与引入确认；展示数据来源、错误和不可兼容状态，不用公开演示代替草稿验证。**验证：** 选择/失败/重试/权限的交互测试及 UI build。**交付：** 可操作页面及测试；不得让平台侧访问公司草稿。

## 阶段 3：公司网关与上线

### D1（search agent 先调研，随后单独 general_purpose_task）：网关仓库与服务契约

**前置：** A3；实施前确认独立网关仓库 checkout 真实存在，确认已有代码再确定文件所有权。**任务：** 先输出精确文件清单、现有实现与缺口；随后单独子任务实现鉴权、幂等发布意图、持久化站点/域名/固定 digest/Release 指针与操作状态。公网接口、CMS 与模板实例不获得 Docker Socket；只有隔离的部署 worker 拥有容器操作权限。**验证：** 非法身份、重复/竞态发布与重启恢复测试。无本地仓库则停在研究报告，不虚构可运行代码。

### D2（general_purpose_task，独立网关部署/快照所有权）：镜像验证和原子切流

**前置：** D1 可运行契约、C2 Release 契约、B2 验证身份。**任务：** 网关核验固定 digest/来源，获取并校验站点级不可变内容 Release，持久化已发布快照；准备实例与数据、检查健康及代表页，再原子切换；失败维持旧版本、重试幂等、显式回滚。**验证：** 两公司隔离、CMS 断联继续服务、恶意 Host/站点 ID 拒绝、失败升级与 worker 重启测试。

### D3（general_purpose_task，网关域名/迁移所有权）：域名 HTTPS 与旧站迁移

**前置：** D2 已可切流。**任务：** 平台子域名先可用；自定义域名需 TXT 所有权、DNS 与证书验证后启用；未知 Host 关闭访问。逐站影子迁移，保留旧共享 Storefront 路由到验收结束；失败恢复旧路由。CMS 生产 Compose 现有 `storefront-gateway` 是 Nginx 转发，不得仅改名替代服务。**验证：** TLS、域名冲突、续期、旧站内容/媒体/回滚，备份恢复和单主机容量测试。

### G3（主 Agent + 运维，人工上线闸门）

分别部署两家公司 CMS/网关并验证同 digest 内容隔离、发布/回滚、网关与 CMS 失效、域名、容量和备份恢复；得到生产切流批准后再上线。任何子 agent 的“测试通过”不能替代真实流量验收。

## 下发顺序模板

每次只给 subagent 一个任务 ID，包含其“前置、文件所有权、任务、验证、交付”原文及仓库绝对路径。研究任务明确“只读”，实施任务明确“允许写代码但不提交、不 push、不改仓库公开状态”；交付给主 Agent 后先做需求复核，再做测试和信任边界复核。并行仅下发不同仓库或完全不重叠文件的任务；共享契约更改先暂停依赖任务并同步所有消费者。
