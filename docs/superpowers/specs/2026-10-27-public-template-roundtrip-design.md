# Public template roundtrip, first AeroFrame version

User approved public reuse of templates on 2026-10-27 after requesting publication, CMS import, content editing and independent-site publication. Existing GitHub repositories are already public. Implement the previously approved public Git + GHCR architecture. Preserve the deployed demo and existing sub2api services. This milestone is functional validation, not general production acceptance.

## Shared contract

Fixed trusted repository: `tangtianshuo/Independent-Website-Templates`. Catalog location: `registry/index.json` on its `registry` branch. Resolve that branch through the GitHub commits API to a 40-character commit before fetching the index; use only raw.githubusercontent.com with redirects rejected. Each record pins its immutable source commit. No caller-supplied URLs.

Index: `{schemaVersion:1,records:PublishedTemplateRecord[]}`. A record is `{schemaVersion:1,id,version,manifestChecksum,imageRepository,imageDigest,sourceCommit,manifestPath,status:'available'}`. Both checksum and image digest use `sha256:` plus 64 lowercase hex digits. Repository is exactly `ghcr.io/tangtianshuo/independent-website-templates/<id>`. Manifest path is exactly `templates/<id>/<version>/template.json`. Source commit is exactly 40 lowercase hex digits. IDs are lowercase kebab-case; versions are numeric x.y.z. Duplicated id/version records are rejected. Unknown/invalid records cannot be imported. Limit responses, impose timeouts, forbid redirects and arbitrary hosts. Publication metadata uses recursively sorted object keys by binary string comparison, arrays preserved, UTF-8 JSON, SHA-256.

The source manifest extends schemaVersion 1 with `presentation:{theme,demo,showcase?}` matching the CMS PresetManifest visual/default-content fields. Existing models/pages/assets remain; compatibility is `{cmsSchema:1,releaseSchema:1}`. Manifest checksum covers presentation too. Release output continues to be schemaVersion 1, with presentation flattened into the existing content.preset contract. Only existing AeroFrame-compatible page layouts and model keys are supported for this milestone; incompatible shapes must be rejected explicitly. Keep existing 1.0.0 files unchanged; publish a new 1.0.1.

CMS persists a normalized PresetManifest snapshot plus the exact publication record on the SiteInstallation (`publishedTemplate`). Subsequent page editing, preview and Release construction use that stored snapshot, not a network lookup or current catalog. Preserve all builtin presets. Public registry refresh does not upgrade installed sites.

Explicit adoption of a newer public version into the existing same-id AeroFrame site must require expectedUpdatedAt, validate model/field compatibility, and preserve existing model/prop IDs, entries, pages, theme and user edits. Do not reinterpret import retry as upgrade. When no site exists, importing a selected record creates a normal draft. Bind Gateway target to a single selected CMS site for this rollout; reject another site using the same global Gateway target. Do not claim general provisioning or multi-tenant rollout.

Gateway TemplatePin adds nullable imageRepository, manifestChecksum, sourceCommit for legacy compatibility. New public pins require all fields and approved registry matching. Service-authenticated PUT `/api/v1/sites/:siteId/template-pin` body `{templateId,templateVersion}` resolves the record independently; transaction locks site, verifies owner, rejects mutation while a publish operation is pending, and preserves the active deployment. Existing published content remains available until a new candidate is ready.

Service-authenticated GET `/api/v1/sites/:siteId/publish-operations/:operationId` returns safe id/status/failureCode/releaseId/revision fields only after workspace/site authorization. Site GET keeps revision and adds safe active deployment fields if needed. Worker pulls only the approved fixed GHCR repository@digest before candidate creation, checks immutable identity, and validates Release metadata against all public pin fields again at finalization. Legacy local digest mode remains supported. Do not expose Docker socket to CMS/control/template containers.

CMS explicit Gateway publication uses persisted publication pin, GETs current Gateway desiredRevision, persists/reuses a local publish intent (release bytes/id + idempotency key) for retries of the same request, uploads Release, then creates the operation. Race conflicts remain explicit; do not blindly override them. UI sends a stable request key per publish action, shows pending/ready/failed, polls authenticated CMS status proxy, and opens the configured site URL only after ready. Only the bound site's Gateway history/state is returned. Legacy local publish remains usable for unbound sites. Do not imply local rollback rolls back Gateway.
