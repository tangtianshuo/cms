# Versioned branch delivery

User-approved requirements: all three repositories use master as the default trunk. Pushes to release/vMAJOR.MINOR.PATCH run CI, publish immutable-digest images, and deliver to ubuntu@101.33.78.203. Master and PRs run verification only. CMS and Gateway update their existing Compose services. Templates publish registry records and pre-pull the image on the server; adopting a new template and publishing site content remain explicit CMS actions.

Existing services and data remain under /opt/novaintelligent/deploy, project nova-cms-validation. Deployment uses a dedicated SSH user with per-repository forced-command keys, an allowlisted root-owned Python deployer, fixed GHCR repositories, validated digest/revision/version/run number, shared filesystem lock, temporary registry credentials, local protected backups, health and public-page verification, and restoration of the previous Compose configuration on application failure. Gateway migration is additive; image rollback never promises database migration reversal. CMS replacement recreates its network-namespace sidecar. Registry publication remains immutable for each template id/version.

CI uses pinned official Actions and Node 22, and integration databases isolated from online data. A release job deploys by digest, verifies source revision labels, and refuses stale run numbers. Main branches and original workspaces retain existing uncommitted user edits. First application release version is 1.0.0; the next unpublished AeroFrame template version is 1.0.2, leaving online 1.0.1 adopted.
