# CMS Studio 可视化页面编辑器设计

日期：2026-10-31

2026-11-06 补充：唯一内容编辑工作区与实时预览以 [补充设计](2026-11-06-single-content-workspace-design.md) 为准；本文件中的布局模型和权限约束继续适用。

## 背景

当前 CMS Studio 已支持页面草稿、页面蓝图、`sectionConfigs`、导航树、草稿预览和发布校验。页面区块目前通过表单和“上移/下移”按钮调整，导航通过表单、分组选择和上移/下移按钮调整；新增页面也已经能从模板蓝图创建内容并绑定页面。

本需求把这些能力组合成可视化编辑流程，让运营人员可以在一个编辑器中预览页面、拖拽调整区块、管理导航、从蓝图新增页面，并继续沿用当前草稿、预览、发布和并发校验模型。

## 目标

1. 用户可以在可视化页面预览中识别并选中页面区块。
2. 用户可以拖拽区块改变页面顺序、添加允许的区块、显示/隐藏区块并编辑区块属性。
3. 用户可以拖拽调整导航顺序和层级，新增分组，并把已启用的静态页面加入导航。
4. 用户可以从现有页面蓝图新增页面，填写标题、路径和内容，保存后直接进入可视化编辑器。
5. 所有修改先进入本地草稿并自动更新预览，显式保存后持久化；发布继续由现有发布中心执行。
6. 保持当前模板能力边界、权限模型、路径校验、媒体引用校验和 `expectedUpdatedAt` 并发保护。
7. 第一阶段的模板区块编辑不能阻断后续结构化自由排版；未来可在同一份页面文档中加入容器、栅格和嵌套组件。

## 非目标

- 第一阶段不开放结构化自由排版能力，不支持任意像素定位、绝对定位或任意自定义 CSS；数据模型必须为后续容器、栅格和嵌套组件预留扩展点。
- 第一阶段不允许添加模板蓝图未声明的区块。
- 第一阶段不改变 Storefront 的路由体系、发布网关或模板安装流程。
- 第一阶段不引入实时协作编辑、自动保存或跨页面撤销历史。

## 用户流程

### 编辑已有页面

用户从“网站内容”下的页面/商品列表或其他快捷链接进入唯一内容编辑工作区。编辑器加载页面草稿、绑定内容、允许的区块、素材和站点导航。中间预览显示当前草稿页面，用户点击区块后，右侧面板显示对应属性；拖动区块时显示插入位置，释放后更新区块数组顺序。编辑过程中不保存、不点击预览也自动更新画布；用户点击“保存草稿”后提交内容和页面设置，顶部状态显示保存结果。全屏预览只作只读检查，“发布更新”继续跳转到发布中心。

页面内容与页面设置共用一个编辑会话与顶层保存状态，可在明细中指出未保存部分。保存按内容、页面、站点设置顺序执行，部分成功不显示全部已保存；版本确认及失败保留按补充设计处理。若用户切换页面、离开路由或关闭浏览器，存在未保存修改时必须提示。保存冲突保留本地编辑状态，用户明确选择放弃前不得刷新覆盖。

### 新增页面

用户点击“新增页面”，先从站点提供的页面蓝图中选择页面类型。向导显示蓝图标题、说明、固定或可编辑的路径规则、需要绑定的内容模型和初始区块。用户填写标题、路径和内容字段后提交；后端在一次受版本保护的操作中创建内容条目、创建页面草稿并绑定条目。创建成功后直接打开可视化编辑器。

新页面提供“加入主导航”选项。勾选后，创建成功的静态页面会追加到导航草稿；动态路径页面不出现在可选导航页面中。

### 管理导航

用户在编辑器左侧打开导航管理；网站设置中的导航入口定位到同一工作区。导航节点分为页面节点和无链接分组节点。页面节点可以在同级移动、拖入分组、从分组移出；分组可以嵌套到模板允许的层级。用户可以编辑标签、切换显示状态、添加分组和从已启用静态页面中添加页面。页面链接不能重复，导航草稿保存时继续由后端校验链接是否对应可发布页面。

所有拖拽操作必须提供键盘等价操作：焦点节点支持上移、下移和切换所属分组；拖拽过程中显示可访问的拖放目标描述，不能仅依赖颜色或位置传达状态。

## 编辑器布局与交互

编辑器采用三栏桌面布局，小屏时折叠为“页面/导航”“预览”“属性”三个可切换面板。

- 顶部栏：返回页面列表、当前页面标题、草稿状态、保存草稿、预览草稿和发布入口。
- 左栏：页面列表、当前页面区块列表、导航树。区块列表和导航树均支持拖拽；当前选中项用焦点轮廓标识。
- 中栏：复用 `DraftSitePreview` 的草稿预览。预览层提供区块 hover、选中、滚动到区块和当前页面路径切换，不改变真实站点路由。
- 右栏：区块属性、页面基本资料、SEO、绑定内容、显示状态和导航状态。属性控件沿用现有字段组件与素材选择器。

预览与 Studio 之间使用明确的消息协议同步选择状态。Studio 向预览发送当前页面和选中节点；预览向 Studio 回传节点点击和 hover 事件。消息必须包含页面 key、节点 ID 和节点 type；未知消息被忽略，避免旧预览版本导致编辑器异常。

拖拽行为采用指针事件实现，不依赖未纳入项目的重量级拖拽库。拖拽只在合法插入位置结束时提交本地状态；取消、按 Escape 或拖出编辑器时恢复拖拽前状态。区块仍遵循当前页面布局的唯一类型约束，第一阶段不支持同一类型的多个实例。拖拽状态机与节点操作必须以稳定节点 ID 为基础，不能把数组索引作为未来布局树的永久身份。

## 数据模型与边界

### 页面区块兼容层

现有模板渲染器继续读取 `SitePage.sectionConfigs`，以保证已有页面和发布快照兼容。编辑器保存时通过布局文档适配器生成 `sectionConfigs` 投影；后续自由排版可以逐步切换到布局文档渲染，不需要一次性重写所有模板。

现有字段保持兼容：

```ts
interface SectionConfig {
  type: string;
  enabled: boolean;
  data: Record<string, unknown>;
}
```

数组顺序是渲染顺序；`enabled` 控制显示；`data` 由区块类型决定。`sectionConfigs` 继续作为兼容字段保留；第一阶段新增的布局文档字段是可选的，不要求一次性迁移历史页面。编辑器内部使用稳定节点 ID 作为选择标识，保存时再按节点顺序生成兼容数组。

### 可扩展布局文档

新增可选的 `layoutDocument` 字段，作为未来结构化自由排版的规范化模型。第一阶段可以由 `sectionConfigs` 派生并保存平面节点；已有数据没有该字段时，读取边界必须自动生成等价文档。

```ts
interface LayoutDocument {
  version: 1;
  mode: 'template' | 'structured';
  root: LayoutNode[];
}

interface LayoutNode {
  id: string;
  kind: 'section' | 'container' | 'component';
  type: string;
  enabled: boolean;
  props: Record<string, unknown>;
  children: LayoutNode[];
  layout?: {
    display?: 'flow' | 'grid' | 'flex';
    columns?: number;
    gap?: string;
    align?: 'start' | 'center' | 'end' | 'stretch';
    responsive?: Record<string, Record<string, unknown>>;
  };
}
```

第一阶段的 `mode` 固定为 `template`，`root` 是扁平 `section` 节点，`props` 映射当前 `sectionConfigs.data`。未来结构化自由排版使用 `mode: 'structured'`，允许 `container` 的 `children` 和受支持的 `component` 类型。布局字段只允许设计系统声明的值，不保存任意 CSS 字符串。

布局文档需要稳定的节点 ID、版本号和迁移入口。发布快照必须保存规范化后的布局文档或其兼容投影，渲染器不得依赖编辑器临时状态。节点操作、选中状态、预览消息、撤销历史和差异比较都使用节点 ID。

### 页面与蓝图

页面创建继续通过蓝图确定 `layout`、`modelKey`、允许的区块、必需区块和路径规则。静态页面允许自定义路径；主页、动态详情页和模板固定路径继续只读。新页面必须绑定当前站点、当前工作区且类型匹配的内容条目。

### 导航

继续使用 `NavigationNode`：

```ts
interface NavigationNode {
  id: string;
  label: string;
  href?: string;
  children: NavigationNode[];
  enabled: boolean;
}
```

前端负责拖拽后的树操作，后端 `normalizeNavigation` 负责清理 ID、兼容旧 `path` 字段、检查重复链接、检查链接是否对应可发布页面和检查节点结构。导航树与未来布局树共享拖拽状态机的纯函数约定，但使用不同的领域校验器。

## API 与数据流

现有接口保持为主路径：

- `GET /api/v4/studio/site`：返回当前站点、页面、蓝图、页面区块选项、导航和可访问内容。
- `POST /api/v4/studio/pages`：使用 `operationId` 和 `expectedUpdatedAt` 创建页面、内容条目和绑定关系。
- `POST /api/v4/studio/pages/:pageKey`：保存页面资料、区块顺序、区块配置、绑定内容、启用状态和导航状态。
- `POST /api/v4/studio/settings`：保存主题、站点设置和导航树。

前端保存时提交当前编辑器对应的完整页面草稿或完整导航树。页面保存可同时提交 `layoutDocument` 和兼容的 `sectionConfigs`；后端先规范化布局文档，再生成模板投影，并使用站点版本进行乐观并发检查。保存失败不清空本地状态；错误消息映射到现有 Studio 错误摘要，并将焦点移动到错误摘要。

如果新增页面需要同时写入内容和页面，继续复用现有 Studio 页面创建接口；不得在客户端先后调用两个无事务接口造成孤立内容或空页面。创建接口返回完整 `PageDraft`，前端以返回值作为编辑器初始状态。

## 权限与校验

- 没有站点管理权限的用户可以查看有权限的页面和预览，但不能拖拽保存页面设置、导航或新增页面。
- 内容编辑权限与页面管理权限分离；页面区块配置需要站点管理权限，内容字段继续遵循模型读写权限。
- 保存前后都必须检查必需区块、允许区块、重复区块、媒体引用、导航链接和页面路径冲突。
- 新增页面必须检查标题、路径、蓝图、内容模型、工作区归属、站点归属和 `expectedUpdatedAt`。
- 发布前继续执行现有 release checklist，任何草稿不满足发布约束时阻止发布并回链到编辑器错误位置。

## 测试与验收

### 单元和集成测试

- 区块拖拽在头部、中间、尾部插入后数组顺序正确；非法区块、重复区块和必需区块删除被拒绝。
- `sectionConfigs` 与 `layoutDocument` 双向转换后页面语义不变；旧页面无 `layoutDocument` 时自动生成稳定节点 ID；未知布局版本被拒绝并保留原草稿。
- 导航节点可以同级移动、拖入分组和移出分组；循环嵌套、重复链接、未发布页面链接被拒绝。
- 蓝图创建页面时正确创建内容绑定；固定路径、保留路径、重复路径和错误模型被拒绝。
- `expectedUpdatedAt` 不匹配时保存失败且不覆盖站点草稿。
- 编辑画布使用本地未保存的区块顺序、内容和导航；显式保存后再发布，快照与相同草稿的预览结果一致。

### UI 验收

- 鼠标和触控板可以拖拽区块与导航，拖拽占位清晰，取消拖拽不会修改数据。
- 键盘用户可以完成区块上移/下移、导航重排、显示切换和面板切换。
- 375px、768px、1024px、1440px 视口可用；320px 下不出现横向页面滚动。
- 保存、预览、发布的状态和错误可被屏幕阅读器识别；所有图标按钮有中文可访问名称；遵守 `prefers-reduced-motion`。
- 未保存离开提示、权限禁用态、空页面、无蓝图和素材加载失败都有明确反馈。

## 分阶段交付

1. **布局文档与领域状态**：定义 `LayoutDocument`、版本迁移、`sectionConfigs` 投影和区块/导航树的纯函数操作，补齐服务端校验测试，保留现有按钮作为后备操作。
2. **导航可视化编辑**：导航树拖拽、分组嵌套、页面添加、键盘操作和保存状态。
3. **页面区块可视化编辑**：三栏布局、区块拖拽、添加/隐藏、属性面板和素材选择。
4. **预览联动与新增页面向导**：预览选中桥接、蓝图创建流程、创建后自动进入编辑器和加入导航选项。
5. **结构化自由排版基础**：增加容器节点、组件注册表、受控布局属性和响应式断点；模板页面继续使用兼容投影。
6. **发布前验证与体验收口**：并发冲突、权限、响应式、无障碍、错误摘要和回归测试。

## 成功标准

- 运营人员不打开完整模板编辑器，就能完成静态页面区块排序、区块内容编辑、页面新增和导航调整。
- 保存后刷新页面，区块顺序、导航层级和页面绑定保持一致。
- 草稿预览与发布后的页面使用同一套区块配置和导航数据。
- 既有动态详情页、固定模板路径、权限限制和发布校验行为不回归。
