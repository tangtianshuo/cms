# 独立站联系表单与客户线索设计

> 状态：设计稿，待用户审阅。本文定义独立站联系表单、线索管理、邮件通知和统计看板的首期边界；尚未实施。

## 目标

让独立站访客提交联系方式和咨询内容，商家可以通过邮件跟进，并能在 CMS 查看、处理和导出线索。看板提供提交趋势及邮件投递状态。能力按站点和工作区隔离，邮件发送故障不能导致已提交线索丢失。

## 已确认的产品决策

- 每条提交都保存到 CMS，提供查看、管理和导出。
- 表单使用常用字段并支持自定义单行/多行文本字段；首期不做完整问卷构建器。
- 线索持久化后异步发送通知邮件，失败可重试。
- 邮件传输配置在 CMS 实例级，首期使用 SMTP；站点仅维护接收地址。传输凭据由部署配置保管，不写入站点配置或 Release。
- 看板首期展示提交量、提交趋势、待处理线索、邮件待发送/失败状态和近期线索。页面访问到提交的转化率等依赖访客分析的指标后续再做。

## 现状与集成点

CMS 已有工作区/站点权限、多站点安装、受信任域名解析和不可变发布快照。Storefront 公开请求通过域名解析站点，页面内容从当前 Release 读取。站点安装模型位于 `backend/src/presets/site-model.ts`，发布及公开页面接口在 `backend/src/presets` 和 `backend/src/storefront`。

仓库目前没有邮件传输模块或独立站线索/访客分析代码。现有 D2 访客分析仍处于计划状态，访问量与表单提交量应先作为独立指标，避免用未实现的浏览事件计算转化率。

## 方案

### 配置边界

- 联系表单是预制页面区块，配置包括稳定的 `formKey`、标题、提交成功文案及字段定义。字段定义支持姓名、邮箱、电话、留言等常用字段，也允许添加单行或多行文本字段；每个字段有稳定 key、标签、必填状态和显示顺序。
- 表单区块配置进入页面草稿并随 Release 发布，使访客页面和服务端校验使用同一版本的字段定义。
- 站点的邮件接收者和联系表单设置存于按 `siteId` 关联的独立私有设置记录，不进入 Release，也不混入会被页面草稿整体保存的站点安装对象。发送方及 SMTP 凭据来自 CMS 实例级部署配置。
- 表单启用前必须配置至少一个有效接收地址，且实例 SMTP 配置已通过连接检查；未就绪时 CMS 阻止启用表单并说明缺少的配置。运行期间 SMTP 暂时故障不阻止收集已启用表单的线索。

### 数据模型

新增 `ContactLead` 持久化记录，建议字段：

- 身份与租户：`_id`、`workspaceId`、`siteId`、`formKey`、`releaseId`。
- 提交信息：唯一的 `submissionId`、字段 key/value、提交时间、页面路径（不含 query/hash）、来源 hostname。`(siteId, submissionId)` 建唯一索引，浏览器对同一次提交重试时返回原线索结果。
- 商家处理：`status`（`new`、`in_progress`、`closed`）、创建和更新时间。
- 通知状态：`pending`、`sending`、`sent`、`failed`，尝试次数、下次重试时间、最近错误摘要及发送时间。

线索记录同时作为邮件通知任务的持久化来源。worker 使用 MongoDB 原子租约领取待发线索并更新通知状态，避免独立写入线索和任务时出现部分成功；发送操作按线索 ID 构造稳定消息标识，减少重试导致的重复通知。邮件服务仍可能在“服务端已接收、客户端未确认”窗口造成重复投递，后台状态和设计文档应明确此限制。

### 提交流程

1. Storefront 从当前发布页面渲染表单和 `formKey`；预览页不产生正式线索。
2. 浏览器提交字段值及受限页面上下文到公开提交接口，不提交可决定租户归属的 `siteId`、`workspaceId` 或邮箱收件人。
3. 后端从受信任域名解析站点，加载当前 Release 并校验 `formKey`、字段定义、字段长度、必填值和邮箱格式；拒绝未知站点、过期/不匹配的发布配置和伪造字段。
4. 后端执行限流和反垃圾校验，保存线索及 `pending` 通知状态后返回成功。接口不等待邮件传输。
5. 邮件 worker 按租约发送到站点配置的接收地址，记录成功或可重试失败。超过重试上限进入 `failed`，由管理员可查看并手工重试。
6. 提交接口、数据库或邮件不可用时返回明确状态；邮件不可用不撤销已保存线索。线索保存失败时不返回成功。

### CMS 管理与统计

- 在独立站管理入口提供线索列表和详情，可按时间、状态、表单筛选；支持将状态更新为处理中或已关闭，查看通知状态及重试通知。
- CSV 导出复用列表查询和站点权限过滤，限制导出数量，并对以 `=`, `+`, `-`, `@` 开头的值进行公式注入防护。
- 独立站数据看板增加提交总量、按日趋势、待处理数量、邮件待发送/失败数量及近期提交。所有指标注明所选时间范围和统计时区。
- 首页/页面浏览量、PV/UV 和表单提交量分开呈现。访客分析完成并具备一致的会话/页面归因后，再定义转化率。
- 权限沿用服务端 workspace/site 授权；普通内容编辑者不能因掌握站点 ID 读取线索。线索查看、状态变更和导出必须服务端过滤。

### 隐私与滥用控制

- 只收集表单定义允许的字段；不接收任意属性，不长期保存完整 IP、完整来源 URL、query 或 hash。
- 公开接口设置请求体、字段数和字段长度上限；对站点及来源做限流，使用 honeypot 或等效低摩擦反垃圾机制，并保留扩展验证码的接口空间。
- CMS 应提供线索删除能力和实例级保留配置；建议默认在创建 365 天后删除线索，管理员可按业务和隐私要求调整。该默认值是产品策略，不代表法规合规期限。
- 邮件主题和正文将访客输入作为纯文本编码，不能解释为 HTML 或邮件头；访客地址仅用于回复信息，不能直接作为邮件 `From`，避免伪造发件人和邮件头注入。

## 接口与模块边界

首期建议新增后端 contact 模块，职责包括表单解析、提交校验、线索存储、管理查询、状态变更、导出和投递 worker；SMTP 由独立 transport adapter 包装，后续可扩展其他传输方式。

- 公开提交：`POST /api/v4/storefront/leads`，以可信 host 推导站点，只接受当前 Release 内已发布表单的字段。
- CMS 管理：在 `/api/v4/storefront/leads` 下提供授权列表/详情/状态/重试/导出接口；所有读写按已授权 workspaceId + siteId 过滤。
- 站点配置：新增独立的站点私有联系设置记录和管理接口维护接收者，收件地址需校验并限制数量；不修改现有页面草稿整体覆盖语义。
- worker：在现有后端进程作业机制中执行有界批处理、租约、指数退避和失败状态记录；首期不引入外部消息中间件。

具体路由命名可在实施计划阶段与仓库现有 API 风格核对后定稿。

## 分阶段交付

1. **表单配置与渲染**：扩展页面区块 schema、预览和发布校验；Storefront 渲染常用字段及自定义文本字段；配置随 Release 固化。
2. **线索 API 与邮件投递**：新增线索模型、站点私有通知设置、提交验证、限流、SMTP transport 和租约重试 worker；保证持久化优先和邮件故障可恢复。
3. **CMS 线索管理**：实现列表、详情、处理状态、通知重试和受限 CSV 导出；增加中英文界面文案。
4. **数据看板与运营验收**：加入提交量与邮件状态指标；覆盖多站点权限、发布/回滚、垃圾提交、SMTP 故障恢复、删除/保留和导出安全。

## 验收标准

- 已发布表单能在正式站点提交，草稿预览、演示页和未知域名不能创建线索。
- 后端以域名解析站点，不接受客户端伪造租户；字段只允许当前 Release 中定义的 key 和类型。
- 成功提交后即使 SMTP 不可用，线索仍可在 CMS 查到且接口不会等待邮件发送；恢复 SMTP 后任务可重试并更新状态。
- 同一个 worker 任务并发领取时不会被多个 worker 同时处理；重试和人工重发有可观察状态。
- 工作区 A 的成员无法通过更换 ID、筛选参数、详情、导出或重试接口访问工作区 B 的线索。
- Dashboard 汇总与线索列表在时间范围和站点过滤下口径一致；邮件失败数不与线索提交数混为一谈。
- 长度/类型校验、限流、反垃圾机制、纯文本邮件编码、CSV 公式注入防护及删除/保留行为均有覆盖。

## 主要风险与未纳入范围

- SMTP 投递不等于收件箱送达；首期看板只反映传输服务接受/拒绝状态，不宣称读信或送达。
- 消息队列和邮件供应商专属事件回调不在首期范围；有规模数据后再考虑外部队列、退信处理和更丰富的邮件可观测性。
- 自动化营销、客户 CRM、自动回复、附件上传、下拉/多选/条件逻辑表单、订单转化和跨站点联系人合并不在首期范围。
- 访客浏览到表单提交的转化率依赖 D2 访客统计完成和共同归因规则，后续单独纳入。
