# 独立站运营指南

这份指南面向日常维护网站的内容人员。所有操作都从 CMS 的当前网站开始，内容保存为草稿，确认预览无误后再发布。

## 本地 Docker

启动本地环境前，确认 Docker Desktop 正在运行，然后在项目目录执行：

```bash
docker compose up -d
```

打开 CMS 地址后选择网站。停止本地环境使用 `docker compose down`；这会停止容器，不会删除数据卷。更新代码后重新构建并启动：

```bash
docker compose build
docker compose up -d
```

## 生产部署

生产环境使用单独的 `.env`，至少配置数据库管理员凭据、JWT 密钥、CMS 和 Storefront 公网地址，以及 Gateway 和域名校验密钥。先在维护窗口执行健康检查，再启动生产编排：

```bash
docker compose -f docker-compose.prod.yml up -d --build
docker compose -f docker-compose.prod.yml ps
```

停止服务使用 `docker compose -f docker-compose.prod.yml stop`；保留数据卷的重启使用 `start`。升级前先创建 CMS 备份并记录当前 release ID，升级失败时回到上一镜像版本并执行 `up -d`，再在“运营状态”和“发布更新”中确认线上 release 仍为旧版本。不要删除 `db-data`、`uploads` 或 `backups` 数据卷来排查问题。

生产 HTTPS 终止和自定义域名接入需要由部署人员在入口代理或证书系统中完成；CMS 只有在域名检查返回“已就绪”后才显示可用状态。

## 日常运营

在“网站内容”中修改页面、商品、导航、轮播图和详情区块；在“素材库”上传图片。预览和发布使用同一份页面内容，发布失败时当前线上版本继续提供服务。

“运营状态”页面显示当前站点的域名、HTTPS 接入、备份、Storefront、Gateway 和最近发布记录。状态为“待处理”或“未知”时，不要把它当成已上线证据，应先打开对应入口确认。

## 域名与 HTTPS

在“设置”或“站点域名”中添加域名，按页面给出的 TXT 值完成归属验证，再按照运维提供的 CNAME 或 A 记录接入。仅添加 DNS 记录不代表 HTTPS 已配置；只有检查结果为“已就绪”才表示 CMS 观察到了成功接入。

## 备份与恢复

在“高级工具 → 成员、语言与备份”创建备份，并等待状态变为“就绪”后再下载。恢复会覆盖 CMS 数据，开始前先确认已经下载当前备份，并安排维护窗口。恢复完成后重新检查当前网站、域名和最近发布状态。

## 发布、更新和回滚

先保存草稿，再打开“发布更新”执行检查。检查通过后发布；发布历史中可以查看版本并回滚到仍然保留的公开版本。模板能力变化需要先采用新模板版本，普通内容、图片和导航更新不需要重新安装模板。

## 失败排查

先刷新“运营状态”和“发布更新”。如果发布失败，记录页面显示的失败原因和操作时间；不要删除当前线上版本。域名问题优先检查 TXT 归属、DNS 指向和 HTTPS 证书。若 Storefront 或 Gateway 显示“未配置”或“未知”，说明当前环境没有足够的服务证据，需由部署人员检查配置。

本地 Docker 配置不代表已经完成生产部署、真实 HTTPS、邮件投递、支付或 Gateway provisioning；这些能力必须在目标生产环境单独配置并验证。
