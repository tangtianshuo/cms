# 电商建站平台架构方案

## 目标

让商家选择一套店铺主题，在 CMS 中维护商品、分类和页面内容，通过可视化配置调整页面，并实时预览、发布和运营一个可访问的电商网站。主题由平台开发和维护；店铺用户通过受控配置定制页面，不直接编辑或上传 Nuxt 源码。

本方案聚焦建站、内容展示、预览和发布架构。购物车、支付、订单、库存、物流等交易域需要独立定义业务模型和服务边界，不应被当作页面主题能力的一部分。

## 核心设计

```text
CMS 管理端（现有 Vue + Vite）
  内容模型、Entry、页面配置、主题选择、草稿预览、发布管理
                    │ 私有/公开 API
                    ▼
CMS 后端与数据库 ─────────────── Nuxt Storefront
  内容、媒体、发布版本、域名绑定     域名到站点匹配、SSR、主题组件、页面路由
                                         │
                                         ▼
                                      访客浏览器
```

管理端和 Storefront 是不同的应用职责。初期可以由同一台服务器或同一套容器编排部署，之后可独立扩容；不需要为每个商家创建一份 Nuxt 应用或复制一份数据库。

域名注册、DNS 解析、HTTPS 证书和 CDN 由 Cloudflare 等外部平台维护。CMS 提供站点与域名绑定、归属验证、接入检查、主域名管理和内容发布；Storefront 的域名匹配是应用层站点查询，不是 DNS 托管。首期由商家人工配置外部平台，无需向 CMS 提供 Cloudflare API Token。

## 模板与数据的边界

平台中需要明确区分以下对象：

| 对象 | 职责 | 维护方 |
|---|---|---|
| CMS 内容模板 | 定义商品、分类、导航等内容字段和数据类型 | 店铺管理员或平台预设 |
| Entry | 保存具体商品、分类或页面内容及语言版本 | 店铺管理员 |
| 网站主题 | 定义颜色、字体、页面布局和区块组件 | 平台主题开发者 |
| 页面配置 | 选择页面布局、区块顺序/显隐和字段绑定 | 店铺管理员 |
| 发布版本 | 固定可对外访问的页面配置、主题版本和内容版本 | 发布流程 |

CMS 不生成每家店铺专属的 `.vue` 文件。页面配置使用带版本号的 JSON 描述区块类型、字段绑定和区块设置；Nuxt Storefront 将这些配置映射到平台维护的组件注册表。未知区块、无效字段绑定或不兼容的配置必须在保存/发布前报错，不能执行任意用户脚本。

示意配置：

```json
{
  "schemaVersion": 1,
  "pageType": "product-detail",
  "sections": [
    { "type": "product-gallery", "source": "product.images" },
    {
      "type": "product-information",
      "fields": ["name", "price", "description"]
    }
  ]
}
```

主题提供每种页面的默认布局。商家可以替换单页布局、排序/隐藏区块、设置区块选项，并绑定商品字段；全站品牌设置作为默认值，单页覆盖只影响该页。主题升级不得静默覆盖店铺的页面覆盖配置。

## 主题与页面模型

建议逐步增加独立于内容 Template 的建站模型：

- `Site`：店铺身份、默认语言、域名、主题版本和站点设置。
- `Workspace`：成员权限与资源归属，可容纳多个 Site；Template、Entry、媒体和组件按工作区隔离。
- `EntryGroup`：工作区内内容分组，同组同语言不允许名称规范化后重复，跨组允许同名。
- `ResourceShare`：向指定工作区分享 Entry、媒体、组件的显式授权、版本与复制来源。
- `Theme` / `ThemeVersion`：主题元数据、支持的页面类型、区块清单、配置 schema 和兼容范围。
- `Page`：稳定路由、页面类型、语言、当前草稿配置及页面级 SEO 设置。
- `Release`：不可变发布快照，引用主题版本、页面配置版本和所需内容版本。
- `SiteDomain`：自定义域名、站点归属、主域名/别名、归属验证和外部接入检查状态；不承载证书签发任务。
- `VisitEvent` / `VisitAggregate`：正式站点浏览事件与按站点聚合的流量、页面及渠道统计。

现有 Template/Entry 可以继续作为内容模型与内容实例。页面配置通过稳定的内容字段标识符绑定数据，不依赖易变的中文显示标签。多语言页面按明确的语言路由和回退规则解析。

## 预览与发布流程

### 草稿预览

1. 编辑器维护当前未保存的 Entry 和页面配置。
2. 管理端将草稿数据通过受保护的预览接口或受限预览令牌传给 Nuxt；预览令牌应短时有效、限站点/语言/版本，并禁止索引。
3. Nuxt 使用正式站点相同的主题组件和页面解析器渲染预览。
4. 编辑变更后更新预览数据。预览可以读取编辑器本地状态，避免必须先保存才能看到输入效果。

预览令牌不得授予写权限，不得暴露长期 CMS 凭证。预览路由需设置 `noindex`，并阻止未授权访问。

### 正式发布

1. 校验页面 schema、字段映射、必需内容、主题兼容性、路由冲突和 SEO 必填项。
2. 创建不可变 `Release`，记录主题版本、页面配置、内容版本/发布时间和生成时间。
3. 将站点当前发布指针原子切换到新版本；失败时继续提供上一版本。
4. 清理或更新受影响的页面缓存、站点地图和 CDN 资源。
5. 保留历史发布版本，支持一键回滚。

发布 MVP 使用 Nuxt SSR 读取已发布数据，不在每次发布时把所有 Entry 复制到另一套数据库。静态生成可作为后续性能优化：由发布事件触发构建和 CDN 上传，但交易和库存等实时能力仍通过业务 API 提供。

## Storefront 运行方式

- Nuxt 作为独立 Storefront 应用，管理端继续使用现有 Vue + Vite 架构。
- 请求进入时根据主机名解析 `SiteDomain -> Site`，再按路径、语言、页面类型找到发布快照。只信任已配置入口网关的域名转发信息，拒绝未知或未启用域名。
- 商品详情、分类等公开页面使用 SSR，首个 HTML 响应包含主要文本、标题、canonical 和结构化数据。
- 对不常变化的内容使用可控缓存；发布、商品更新、主题变更时按站点/路由失效缓存。库存、价格等高频变化数据采用业务 API 或短时缓存策略。
- 页面缺失返回正确 404；预览、管理端、购物车和结账路由使用各自的访问控制与索引策略。
- 媒体通过现有媒体存储或对象存储提供，图片缩放、格式转换和 CDN 缓存作为独立能力规划。

## 主题维护

主题是需要持续维护的软件产品，不是一次性静态文件。主题维护流程建议包含：

- 每个主题版本有明确版本号、兼容的配置 schema、页面类型和区块清单。
- 新主题版本先在测试站点和演示数据上验证，再逐步开放升级；店铺升级前显示变更摘要和影响范围。
- 主题配置 schema 变化提供迁移函数；不能迁移的旧配置保留原版本渲染，不自动丢弃用户设置。
- 标记弃用的区块应给出替代方案和迁移期限；删除区块前提供迁移工具和恢复方案。
- 维护主题目录、预览环境、变更记录、已知限制和支持范围。
- 发布主题版本前检查页面在常见视口和语言下的布局，检查无效绑定、资源加载、可访问性和性能预算。

## 网站运营维护

平台运维至少覆盖以下日常能力：

- **域名接入**：绑定站点、域名所有权验证、DNS/HTTPS 外部接入检查、主域名切换、重复域名和恶意绑定防护；DNS 修改和证书签发/续期由外部平台负责。
- **发布运维**：发布状态、失败原因、构建/缓存任务状态、历史版本、一键回滚和操作审计。
- **可靠性**：数据库与媒体备份、恢复演练、健康检查、错误告警、请求日志和发布事件追踪。
- **性能**：CDN、SSR 缓存、数据库查询限额、图片处理队列和热门店铺隔离策略。
- **安全**：店铺间数据隔离、预览授权、速率限制、管理操作审计、密钥轮换和输入内容校验。
- **SEO 运维**：站点地图自动更新、robots 与 canonical 检查、发布页索引状态、结构化数据检测和重定向管理。
- **店铺管理**：站点暂停/恢复、配额、使用量、异常流量、主题升级状态和运营通知。
- **访客统计**：正式页面 PV/UV/访问次数、来源渠道、热门页面与商品、404 路径；异步采集、去重、站点授权、隐私同意和保留策略。此类统计与服务监控、Cloudflare 边缘请求统计分别展示。

需要定义服务指标和告警阈值，例如 storefront 5xx 比例、页面响应时间、发布成功率、域名/TLS 失效、缓存刷新失败和备份任务失败。具体阈值应依据实际部署和业务目标制定，而不是写死在主题配置中。

## 分阶段交付

### 阶段一：验证页面渲染链路

增加一个 Nuxt Storefront 应用和一个商品详情主题；定义商品内容模型、页面配置、字段绑定和域名/站点开发环境解析。先支持一个站点、一种语言和一个产品详情页。实现基于当前未保存内容的实时预览。

### 阶段二：主题、页面和发布

增加首页、商品列表/分类页和详情页；支持主题选择、页面区块配置、单页覆盖、多语言、草稿/发布、不可变发布记录、回滚和预览授权。

### 阶段三：正式店铺运营

先交付外部平台托管下的域名绑定和访问解析（D1），随后交付多独立站、多工作区、多个模板安装共存、Entry 分组同名约束与跨工作区资源共享（D3），再交付访客统计采集、聚合及后台报表（D2）。CDN/缓存失效、备份恢复、发布监控、主题升级迁移和运营告警另列 D4。DNS、HTTPS 证书和 CDN 的维护仍归外部平台；CMS 显示接入检查结果和配置指引。

多个独立站可安装同一或不同预制模板，每站点分别保存页面、主题及发布指针；域名解析到工作区和站点，管理操作另行验证成员权限。工作区内 Entry 支持分组，同组同语言的名称规范化后唯一，不同组可同名。Entry、媒体和受控组件默认私有，跨工作区使用显式共享及复制导入；共享依赖、版本、撤销、媒体保留和发布快照均纳入验收。

实施计划见 `docs/superpowers/plans/2026-10-23-storefront-domains-phase-d1.md`、`docs/superpowers/plans/2026-10-23-storefront-workspaces-phase-d3.md` 与 `docs/superpowers/plans/2026-10-23-storefront-analytics-phase-d2.md`；口径与验收以 `storefront-preset-solution.md` 第 6.1–6.3 节为准。

### 阶段四：规模化与高级定制

按访问量引入静态生成/增量构建、异步发布队列、主题市场、开发者主题 SDK 和可选的受控扩展机制。任意代码主题应在独立构建/运行边界内执行，并作为单独的安全与运维项目评估。

## 主要风险与决策

- **字段语义不统一**：通过商品等领域模型约定、明确的字段绑定 UI 和发布前校验解决；不要根据字段名猜展示含义。
- **主题升级损坏页面**：使用版本化配置、兼容矩阵、迁移和不可变发布快照。
- **跨店铺数据泄漏**：所有 API 查询都必须以已验证的站点身份做租户过滤；不能只依赖前端传来的 site ID。
- **缓存展示旧内容**：发布事件必须携带受影响的路由和资源，并有可观测的失效任务与回退策略。
- **功能范围膨胀**：建站页面与交易系统分阶段；订单、支付、库存和物流需单独立项。
- **仓库维护状态**：当前 README 声明该公开仓库已停止维护。正式投入实现前，应确认后续开发基于自有维护分支/代码库，并明确升级与安全修复责任。

## 建议结论

采用“现有 CMS 管理端 + CMS 后端/数据库 + 独立 Nuxt Storefront”的模块化架构。主题代码由平台维护，CMS 保存版本化的页面配置和内容，不生成店铺专属 Nuxt 源码。预览和正式发布共用 Storefront 渲染器；发布创建可回滚的不可变版本。初期动态 SSR、同机部署、多站点逻辑隔离；成熟后再独立扩容，并按流量和缓存需求引入静态生成。
