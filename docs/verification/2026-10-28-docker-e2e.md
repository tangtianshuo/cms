## 本轮修复

1. **CMS Docker 预览 origin 无构建入口。** 新增两个明确 build ARG，确保生产镜像 UI 指向本地精确的 storefront/1.0.3 renderer origin。镜像内容契约先失败、修复后通过；CSP 仍保留精确来源、self 和 frame-ancestors 保护。
2. **Gateway worker CLI 静默退出。** 绝对文件路径用手工 file URL 比较导致入口未执行；改用 `pathToFileURL`。新增真实子进程回归测试，先以“错误配置仍返回 0”复现，修复后按预期执行并返回 1。
3. **ARM 主机无法拉取仅含 amd64 的公开镜像。** 新增受限 `GATEWAY_DOCKER_PLATFORM`，同时用于精确 digest 拉取和候选创建，只接受 `linux/amd64`/`linux/arm64`。未替换公开批准镜像，未放松容器安全选项。配置契约先失败后通过，并由真实 Docker E2E 验证。

测试入口另支持配置需要检查的精确预览 origin，适配本轮隔离端口，保留拒绝任意远程 iframe 的断言。

## 自动回收修复与剩余边界

**原 P1 已修复：Gateway 退役实例自动回收。** 首次 13/11 的历史审计与手工清理证据继续保留。新增数量断言先在旧 worker 上真实失败（预期最多 2 个，实际 3 个），随后实现并复测通过。修改前代码备份位于 `/Users/445101599qq.com/Projects/cms-backups/gateway-gc-20261028-143051`。

- worker 启动及轮询期间约每 5 秒扫描；每轮最多尝试 10 个容器。独立受限回收客户端不会扩大原候选创建客户端的权限。
- 对站点持有与发布入口一致的 Site 行锁；存在任何 pending 操作（包括过期租约）、数据库活动元组与路由不一致或数据库不可用时不回收该站点。当前实例与前一条恢复备用路由保留，重启后仍保留对应保护。
- 删除前重新 inspect 完整容器 ID，校验站点、工作区、版本、可信 Release/TemplatePin 镜像、命名、非 root/只读/资源限制/安全配置、loopback 端口和无挂载。只删除容器，不删除发布历史、快照、镜像、网络或数据卷。回滚旧快照已在真实流程中再次通过。
- 新增 7 项 worker 回归（5 项 socket/归属校验、1 项真实 PG 协调、1 项路由重启保护）；Gateway 全套 164 项测试通过，0 失败、0 跳过，TypeScript 检查通过。
- 真实发布/回滚后数量断言通过，失败候选保护与重启恢复复跑通过。额外创建 3 个真实残留候选，通过 socket 代理拒绝删除，观测 `removed:0, failed:3`；重启并恢复删除后观测 `removed:3, failed:0`，全部原有 15 个 Docker 容器（包含当前及前一实例）保留，首页 200。整个自动回收验收没有使用手工 prune。

该机制沿用当前单机权威路由设计；多主机/HA 不在本轮范围。归属资料不全、配置异常或活动路由无法恢复的实例会保留供诊断，不能保证这类异常状态也满足 2 个实例上限。Docker 回收失败只触发后续重试，不把已完成的发布改写成失败。

**P2：失败提示缺少明确原因。** UI 能明确显示“发布失败，原有站点继续提供服务”，但候选 `CANDIDATE_UNHEALTHY` 仅映射为笼统提示。建议增加面向使用者的可理解原因与重试指引，技术错误码保留给诊断视图。

- 1.0.3 尚无真实公开 registry 批准记录，因此仅验证本地镜像、SSR、私有预览；其安装数据明确为独立 test fixture，不伪造公开审批。公开发布流程使用真实已发布 1.0.2。
- 本地域名 fixture 不代表公网 DNS 所有权、HTTPS 或 ACME 成功。公网 80/443、证书签发/续期、Linux 服务器生产流量、HA/灾备未在本次本地验收中覆盖。
- 核心业务链路已端到端执行；成员管理、备份恢复等所有后台模块未逐项做浏览器全路径验收，其权限/隔离/保留策略主要由真实数据库集成测试覆盖。
- 原始日志/随机凭据只保留在忽略的运行目录；历史版本备份仍保留。操作脚本没有清空现有开发/生产数据。
