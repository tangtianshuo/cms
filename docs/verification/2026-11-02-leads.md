# P5.1 询盘闭环验证

日期：2026-11-02

本次实现把公开询盘接收从页面渲染链路中拆出。AeroFrame 在发布数据声明 `operations.contactFormEnabled` 且运行时配置 `NUXT_PUBLIC_LEAD_ENDPOINT` 时显示表单，浏览器直接调用 Gateway `/api/v1/sites/:siteId/leads`；未配置时仍保留原联系邮箱入口。

Gateway 负责校验 UUID、来源类型、字段长度、邮箱格式、HTML/脚本输入、honeypot、IP 限流和站点内 dedupe。数据写入 PostgreSQL `Lead` 表，初始通知状态为 `pending`。内部 GET/PATCH 使用 `CMS_SERVICE_SECRET`，CMS 在 Gateway binding 已配置时读取和更新 Gateway 数据；迁移期间未配置 binding 时继续使用本地 repository 适配器。

验证命令：

```bash
node --test --experimental-strip-types apps/ingest/leads.test.ts
npm run typecheck --workspace @gateway/control
npm run build --workspace @gateway/control
npm run build:noEmit --prefix backend
npm run type-check --prefix ui
node --test ui/test/leads.test.mjs
npm run build-only --prefix ui
npm test --prefix ../templates-contract-runtime/templates/aeroframe/1.0.3/storefront
npm run build --prefix ../templates-contract-runtime/templates/aeroframe/1.0.3/storefront
```

结果：Gateway 询盘测试 3/3、CMS UI 询盘状态测试 3/3、AeroFrame storefront 测试 17/17 通过；CMS 后端、CMS UI、Gateway control 和 AeroFrame 生产构建通过。浏览器提交失败只更新表单状态并提供重试，不影响公开页面首屏和已发布 artifact 读取。
